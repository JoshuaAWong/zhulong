# 烛龙 v1.3 综合实施计划

> 日期 2026-10-06 ｜ 状态：待方案把关与审批
> 范围：卡顿专项修复（优先）+ 限流器 + 大户榜 + AGENTS.md + 设置子页/托盘开关 + 图标体系 + G 系白话面板改版

## 0. 背景

- 用户报告光标瞬移/低帧率。首轮误诊 ToDesk（关停后"似乎缓解"），复现后排除。
- 复查证据（2026-10-06，只读）：360ChromeX **32 进程**（三个合计 115% CPU，本机当前最大耗源）；**WmiPrvSE 96%**（WMI 被高频轮询）；无显示驱动事件、GPU 闲置、内存/IO 健康。
- 面板自身嫌疑：十字线联动在**每次 mousemove 对其余 5 张图执行 setActiveElements+update**；30 秒刷新为**全量 destroy+重建 6 张图**。面板页前台时，鼠标划过图表区即主线程打满 → 光标跳帧，与用户症状（移动鼠标帧率低）高度吻合，且时间线与面板上线（10-04）吻合。

## 2. 通用异常进程跟踪（修正案 1，取代米哈游专用白名单）

- **原设计作废**：WATCH_PROCESSES 白名单（HYPHelper.exe > 15GB → kill）——硬编码单一进程，覆盖不了下一个泄漏者
- **新设计·三层**：
  1. **跟踪**：proctop（§3）每 2 分钟落 Top5 commit 进程序列，形成各进程时间序列
  2. **判定**：近 30 分钟窗口增长 >4GB 或 >50%（且当前 >8GB）→ 疑似泄漏；任何进程 >20GB（非保护名单）→ 红线异常。判定函数独立可测（`zhulong/core/anomaly.py`）
  3. **动作分级**：通用异常 → 默认仅告警（toast 一次/冷却 + 大户榜红标 + 待处理建议卡）；自动杀仅限 `config.AUTOKILL` 显式名单（**默认空名单**，用户自加，kill 仍走七步安全链）
- **保护名单 NEVER_KILL**：系统关键（System/Registry/explorer/dwm/csrss/winlogon）、安全软件进程、烛龙自身、ZenlessZoneZero.exe（游戏）
- HYPHelper 专用规则下线，其历史行为作为异常检测首个实测样本
- 把关 delta：通用检测最大风险=误杀 → "默认仅告警 + AUTOKILL 显式名单 + 保护名单 + 七步链"四层吸收，通过

## 2.1 限流器 throttle

- `zhulong/throttle.py`（~100 行）：`apply_if_due(cfg,state,insert_event)` 分频幂等应用；`restore(cfg)` 全量还原
- **规则双层**（config 单点原则的有意识例外，理由：托盘"恢复初始状态"需要一块不被运行时触碰的出厂副本）：`config.py` 存出厂规则（THROTTLE_DEFAULTS，永不改）；`data/throttle_override.json`（gitignore）存用户覆盖；生效=有覆盖用覆盖
- **开关持久**：enabled 状态写 SQLite kv（重启保持）
- **已施加清单持久**（把关修改②）：每次 apply 把"进程名→施加的参数"写 kv；`restore` 按清单还原（不按现行规则），override 删规则后漏网进程也能摘镣铐
- 预填规则：ToDesk.exe / QQPCTray.exe / AweSun.exe / sunloginclient.exe → below_normal + 尾部绑核（"tail:N" 动态取核）
- 红线：priority 仅 normal/below_normal；cores 合法性校验；AccessDenied 跳过；永不处理烛龙自身；事件记 `rule="throttle"` 入面板时间线
- 挂载：scheduler.run_cycle 末尾分频调用（零新增线程/任务）

## 2.5 新维度采集（net / latency / gpu，2026-10-06 追加）

- **net.py**：net_down_mb_s / net_up_mb_s（psutil.net_io_counters 差分，零成本）
- **延迟与抖动**（并入 net.py）：ping 网关 + ping 公网 DNS（223.5.5.5），每 30s 各 1 包；`ping_gw_ms` / `ping_net_ms` / `ping_jitter_ms`（近 10 次标准差）。**明示：烛龙首次主动发包（2 包/30s）**，目标与开关走 config
- **gpu.py**：nvidia-smi CSV 一次取 温度/利用率/显存（`gpu_temp` / `gpu_util` / `gpu_mem_used` / `gpu_mem_total`），分频每 2 周期（1 分钟）一次抑制外部进程开销；**CPU 温度 WMI 实测不可得，放弃**（不引入常驻第三方服务）

## 3. 统一进程大户采集 proctop.py

- 每 2 分钟**一次**进程遍历，一次产出：CPU 大户、IO 大户、commit Top5（值=GB，label=进程名）
- v1.2 的 cpu.py/diskio.py 内进程扫描**下线**（仅留零成本总量指标）→ 扫描次数 2→1，开销不增反降
- 面板新增「大户榜」卡片/分区（Top5 列表，涨水位时一眼锁定元凶）
- 分频常量沿用 `CPU_TOP_INTERVAL=4`

## 4. AGENTS.md（仓库根）
