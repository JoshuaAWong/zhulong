## 手动刷新崩溃及修复

首次实际手动刷新导致新版进程崩溃。.NET Runtime 事件1026的堆栈定位到CodexScanner读取超4MiB日志行时抛出InvalidDataException；该异常不属于IOException，原有捕获未覆盖，后台任务故障随后穿过async void消息处理。

修复显式覆盖DataHub、DesktopWindow与P0 CLI的InvalidDataException处理。维持每批4MiB上限，不通过放大预算绕过大行；出错保留旧快照和可见错误，来源游标不推进，后续正常来源可继续采集。

DesktopSelfTests增加“超限行触发错误 → 游标保持 → 下一正常日志恢复”的真实生产路径用例，总计32项通过。Release修复版已重新部署，保留新版data。修复后再次点击手动刷新，观察到北京时间22:17:13生成新报告且同一新版主进程存活；未把一次成功当成长时稳定性证明。

## 关闭窗口与继续采样

实际关闭窗口后，生命周期记录出现window_closed；被记录的6个WebView子进程实例全部退出。新版主进程仍为同一实例，系统样本数由开窗时514增加到关窗后516，证明关窗后后台仍继续采样。

未以强制GC、结束WebView进程或替换主进程来通过释放检查。关窗后原生进程仍有内存占用；这不等于浏览器残留，也不能据一次样本证明无长期泄漏。

## 进程树资源短样本

| 指标 | 修复版开窗样本 | 关窗后样本 |
|---|---:|---:|
| 进程数 | 7（1个.NET主进程、6个WebView子进程） | 1（同一.NET主进程） |
| private合计 | 479,821,824B（457.59MiB） | 181,596,160B（173.18MiB） |
| working set合计 | 708,120,576B（675.32MiB） | 254,242,816B（242.46MiB） |
| 句柄合计 | 4,384 | 922 |

开窗原始证据为out/desktop/phase-open-fixed.json。working set相加可能重复计算共享页，不能当作私有内存。开窗记录含累计CPU秒，尚未建立同阶段差分CPU、GPU或帧耗时基线；本表不据此填写CPU占用率。不同阶段同时包含后台AI读取与采样活动，内存差值不能全部归因为某一张图或动效。

关窗后另连续观察约239秒：始终只有原生主进程，private从165,347,328B下降到149,880,832B（约143MiB），范围148,574,208–169,324,544B；句柄928→917，累计CPU增加0.984375秒。该阶段包含系统采样和AI后台工作，未做强制GC或内存整理；证据out/desktop/closed-resource-summary.json。

这些为本次正常交互短样本，不能宣称低开销预算、长期无泄漏或压力门禁已经通过。

## 托盘重开与正常退出

- 托盘重开：待完成。需确认同一新版主进程、仅一个窗口、新WebView实例和既有历史保留。
- 托盘正常退出：待完成。需确认主进程及其自有WebView全部退出、退出日志存在、托盘图标消失。

用户协助操作的实际结果尚未记录前，不将这两项标为通过，不改用强杀作为正常退出证明。
