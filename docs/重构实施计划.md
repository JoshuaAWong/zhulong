## 3. 阶段安排

### P0：现状对账与架构可行性验证

P0-A 界面对照已单列 [详细计划和结果](P0界面对照验证.md)，覆盖最小宿主、两种面板、释放观察和受控失败。其余检查仍待完成，不能整项勾选 P0 通过。

**目的**：在大规模迁移前验证 Windows 接口、窗口释放、后台与 AI 负载隔离和测量口径。

**产出**：现有能力/配置/数据清单；固定测试数据集；最小 .NET 宿主与 WebView 生命周期原型；Windows 指标对账；资源报告与明确预算；初步数据目录/回滚方案。需另行细化文件范围后再实施。

**检查项**：
- [ ] 核对 FR/D 到 R-* 的映射，检查本地池功能与 main 差异，不把未合入功能漏掉或默默合入。
- [ ] 固定 Release 构建、硬件、系统版本、采样频率、日志体量与启用功能，区分冷启动、预热后空闲和持续追加。
- [ ] 测量旧版及原型的 CPU、private commit、working set、句柄、读写字节、延迟；汇总自有 WebView/辅助进程。
- [ ] 在隔离会话或虚拟机先完成单次无干扰检查，再执行 100 次面板开关及窗口释放验证；日常桌面禁跑，出现交互异常立即中止。
- [ ] 按 N-08 在隔离环境比较静止/交互/持续动画，以及减少动效/隐藏/关闭；记录 CPU/GPU、帧耗时和采样延迟，真实验证暂停与恢复。
- [ ] 用测试样本模拟大日志和慢提供器，验证系统采样与 UI 不被它们串行阻塞。
- [ ] 在数据副本验证备份恢复与版本隔离；不对用户旧库进行写入试验。
- [ ] 确认需求 Q-05 数值预算与下一阶段范围。

**通过门禁**：指标口径可靠、释放行为达到约定、预算可测、回滚路径实际演练通过；否则调整架构，不扩张功能。

### P1：系统监控与桌面基础闭环

**对应需求**：R-SYS-01/02/03、R-LIFE-01、R-DATA-01、R-UI-01/02/03、R-ENG-01。

**产出**：原生采集 → 最新快照 → SQLite → 托盘/面板/CLI；完整生命周期和基础主题。

**验收**：指标与独立 Windows 数据对账；30 秒及重任务分频按确认值运行；监控/面板故障分别处理；休眠、设备缺失、端口冲突、主动退出、重启、看门狗均覆盖；图表就地更新、联动合帧，显示口径及中文语义一致；基础交互动效与减少动效模式、隐藏/关闭释放按 N-08 验证，宠物的具体动画在 P5 验收。

**回滚**：停止新宿主恢复旧版；旧库及旧配置保持可用。并行观察期间新版不执行自动处置。

### P2：单个 AI 提供器闭环

**对应需求**：R-AI-01/02；目前沿用 Kimi Code 为首个提供器，开工前由 Q-04 确认顺序。

**产出**：发现 → 增量解析 → 去重/计费 → 事务提交游标 → 图表/诊断；明确接口和样例集。

**验收**：人工核定 token/缓存/费用；覆盖追加、截断、轮换、重写、半行、重复来源、重新启动及写库失败；无变化扫描读取量和追加延迟达到 P0 预算；失败不得影响系统监控。

**回滚**：关闭该提供器，系统监控继续运行；保留来源日志和旧数据，不把失败结果发布为零用量。

### P3：规则、受限动作与安全等价迁移

**对应需求**：R-ACT-01/02/03/04，以及相关生命周期与审计要求。

**产出**：统一动作执行入口、手动/自动共享熔断、限流还原、服务重启恢复、池能力核对结论。

**验收**：逐条复用旧版行为约束并新增独立预期样例；真实触发保护名单拒绝、路径不可读、目标消失、PID 复用、计数持久化失败、全组不足龄及服务启动失败；人工与自动路径均验证。危险动作使用专用测试目标，不对正常用户进程做破坏性验证。

**回滚**：先停止新版自动处置、还原已施加的可逆限制，再恢复旧版处置属主。同一目标不能由新旧两套引擎同时自动管理。

### P4：提供器扩展与历史记录使用

**对应需求**：R-AI-01/02、R-DATA-01，需求 Q-03/04。

**产出**：提供器逐项支持清单、标准样例与缺失能力说明；在已确认模式下提供旧记录查看或导入。

**验收**：第二个提供器检验公共接口；不同工具的缓存和累计值语义不互相污染；若做导入，验证幂等、时区、指标改名、重复来源、费用精度、事务失败与数据副本恢复。

**回滚**：禁用新增提供器；导入目标库可恢复，源库不改写。不能用“框架支持”代替每个提供器已通过对账。

### P5：完整桌面体验与可选联网功能

**对应需求**：R-DESK-01、R-OPT-01、R-UI-02。

**产出**：按确认清单逐项交付宠物、挂件、成就；同步、排行榜、Skills 和远程额度分别定义权限及边界。

**验收**：可见/隐藏/关闭时计时器与动画符合预算；完整主题和响应式布局通过；凭据不进 UI/日志；默认关闭选项的出站行为符合清单；禁用/失败不破坏本地数据。

**回滚**：停用单项能力即可恢复核心监控；任何远程数据清理按明确协议处理，不承诺撤回已导出的副本。

### P6：每次发布共用的包装门禁与最终切换

**对应需求**：R-ENG-01、R-LIFE-01、R-REL-01 及 Q-01/07；交付与更新遵循 DEC-08/09。P6 的包装与发布验收随每个可交付版本执行，不必等 P5 所有功能完成；正式替换旧版须另满足动作与完整能力对账。

**产出**：由同一核心产物生成同版本安装包和便携压缩包；各自的运行环境、程序/数据目录说明、升级与退出清理流程；依赖/许可证、旧版切换步骤和回滚包。更新包统一进入程序目录的 updates 子目录；用户确认后，安装版执行安装包，便携版在退出后使用压缩包替换程序文件，保留配置与历史数据。

**验收**：两种交付均跑启动与升级回归；安装版验证安装/卸载，便携版验证解压、目录移动和退出后移除；运行时存在/缺失、目录不可写、升级失败、确认前不执行、两种包类型正确匹配、配置与历史数据保留均覆盖；无硬编码用户路径；单实例、自启与主动退出正确；旧版任务/处置属主不会重复启动；完整回归与 24 小时稳定性报告通过。

**回滚**：切换前演练恢复旧二进制、配置与数据库；不直接降级打开不兼容的新 schema。停用或卸载旧版须进入明确的切换步骤。

### 3.1 首版与完整迁移的依赖关系

- 已确认观察首版（DEC-11）：P0 通过 → P1 系统闭环 + P2 单提供器 → 本版适用的 P6 安装/便携、升级恢复、完整回归和 24 小时稳定性门禁。P3–P5 未交付功能明示，不称“旧版完全替代版”。
- 主动处置在观察首版之后完成 P3 的安全等价、实际执行与权限验收；旧版只在确认切换后停止担当处置属主。
- Q-03 已选择主动一次性导入；未指定必须纳入观察首版，先按 P4 排期，若首版需接入则前移并完成相应验收；若 Q-04 要求首版多个工具，逐个增加验收，不把公共接口存在等同支持完成。
- 完整迁移：需求表每项都有已交付证据；待确认或延期功能继续列出，不通过改名为“扩展”从总范围消失。

### 3.2 发布验收与回滚矩阵

| 场景 | 验收与恢复要求 | 最迟阶段 |
|---|---|---|
| 安装/便携，首次/升级 | 同源码版本、同 schema，正确包类型；无 .NET、无 WebView、目录不可写分别验证；未确认不执行替换 | 每次 P6 |
| 旧历史/重导入/半途失败 | 来源不变，重复不翻倍，批次和时区可追踪；恢复不覆盖导入后新增记录 | Q-03 选择接入的版本 |
| 更新退出超时/文件占用/磁盘空间不足 | 未完成退出不得替换；失败状态可见，旧程序/数据库仍可恢复 | 每次 P6 |
| schema 迁移后启动失败 | 健康检查前不启正常业务写入；恢复二进制+匹配数据快照。开始产生新数据后走保留故障库的人工恢复流程 | 每次含 schema 变化的发布 |
| 便携目录移动/换机器/双形态同时启动 | 旧自启路径不继续拉旧目录，凭据重新授权；同一用户只有一个生产动作属主 | 首次 P6 及相关变更 |
| 新旧版观察/切换/回滚 | 观察版不自动处置；切换先确认旧属主停止，回滚先停止新属主并还原可逆限制 | P3 / 最终切换 |

没有用到的危险场景不在本机临时制造；先用故障注入和专用测试目标验证，再在适用发布环境验收。签名清单、渠道、密钥管理及运行时维护是 P6 工程产出；若出现付费或额外账户需求再提交具体选择，不提前让用户猜安装器细节。

## 4. 每阶段详细计划模板

| 项目 | 必须填写的内容 |
|---|---|
| 范围 | R-* 编号、具体可见行为、不会自动扩大到哪些相邻能力 |
| 现状 | 当前提交、代码属主、调用方、既有测试与样例 |
| 修改 | 文件清单、接口/数据模型变化、依赖及必要性、粗略规模 |
| 成功标准 | 硬门禁与软目标分开；数值口径、测量时段和负载明确 |
| 风险验证 | 至少真实触发每个已设计的失败/拒绝/恢复路径 |
| 回滚 | 二进制、配置、数据、自动处置属主分别如何恢复，演练证据 |
