# P0-A：混合面板与纯 WPF 对照

> 日期：2026-10-28。状态：短检查完成；正式压力对照因干扰任务栏中断，未通过验收。属于 P0 的窗口生命周期子项，不代表 P0 或重构完成。

## 问题与现状

同一 .NET 后台、相同数据与刷新频率下，WPF + WebView2/React 的资源成本及关闭释放行为是否适合烛龙？纯 WPF 是对照，当前主方案仍为混合方案。

现状依据：Python 的 zhulong/collectors/memory.py 用 GetPerformanceInfo 读取 commit；zhulong/core/scheduler.py 在统一循环中分频采集。现有程序继续运行，本实验不调用动作、数据库或部署入口。

## 范围、文件与依赖

- prototypes/p0-ui/：可丢弃的 .NET 10 WPF 宿主、原生面板、WebView 面板、React 静态页及 Python 外部测量器，共用合成数据生成器。
- 不注册自启、服务、看门狗，不建立 HTTP 服务，不暴露文件、命令或配置写能力。
- WebView2 SDK 和 React/ReactDOM 覆盖已选定宿主与前端；esbuild 仅构建实验静态页。P0-A 不引入 Vite 开发服务器、图表库或 SQLite，避免掺入无关变量。
- 官方 .NET SDK 仅解压到忽略目录 out/p0-tools，并核对 SHA512；不改系统 PATH/安装。构建、缓存和原始测量均进入忽略目录。
- 预计实验代码与脚本约 600–900 行；属于新增实验，现有程序代码不变。实现分为宿主、两个面板、静态页、测量器，避免单文件承担全部职责。

## 对照协议

1. Release、同机、同窗口尺寸；相同的 300 点曲线与 50 行列表，每秒刷新一次；窗口可见且不抢焦点。
2. 分别测无窗口基线、面板稳定段、关闭恢复段、100 次开关、最终恢复。时长和浏览器缓存状态记录在结果中；首次创建不是完全冷启动磁盘测试。
3. Python/psutil 在进程外按 PID 与 create_time 跟踪宿主和自有子进程，已发现的子进程脱离父链后仍计入。统计 private commit、working set、句柄、CPU 时间、I/O 和进程数。CPU 同时报单核等效及按逻辑核归一化口径。
4. 开窗就绪和刷新到渲染回调是代理指标，不等同真实用户输入到屏幕的延迟；两种渲染回调机制不同，不用于微小差异排名。
5. Dispose 后通过固定实例的 Windows 进程句柄等待浏览器退出，外部测量再核验残留；10 秒是实验失败检测参数，正式产品期限仍待定标。不调用强制 GC，不以结束浏览器制造释放成功。
6. WebView 仅加载固定本地资源，阻止外部导航；实际触发前端资源缺失，必须非零退出且无残留。
7. 至少观察一次实际面板。原型不是完整国风视觉设计，也不削减正式界面需求。

## 验收和边界

硬检查：数据量一致；各 100 次开关；无未处理异常；自有进程退出；关闭停止刷新并解绑事件；失败路径真实触发；现有全量回归通过。

软比较：稳定资源、开窗与刷新耗时分布。先报告数据，再确认预算，不倒推刚好通过的阈值；不把 working set 回落当作 commit 泄漏已修复。

本轮不覆盖：旧版同功能完整基线、真实 AI 大日志、采样隔离、Windows 指标独立对账、数据库/回滚、托盘/宠物/挂件、24 小时稳定性和安装升级。它们仍待后续 P0/阶段验收。

## 自查（非独立把关）

可实施本实验。更简单的路径是只测当前混合方案；增加纯 WPF 对照能以有限成本验证主要选型分歧。共用生成器和外部测量限制变量，无生产数据改写。产品预算仍待确认，不能宣布正式达标。失败时停止实验即可，原型与缓存独立，无须回滚旧版。

## 实测记录

短检查发现并修正两项实验问题：开窗/关闭过渡曾混入稳定段，现单列 opening/closing；SDK 的 BrowserProcessExited 事件等待曾超时，但外部采样显示进程已消失，现以 Windows 进程句柄退出及外部独立用户目录扫描交叉核验。没有强制 GC 或主动结束浏览器来通过实验。

界面观察使用原型自身的 WPF RenderTargetBitmap / WebView2 CapturePreviewAsync 输出，已确认曲线、列表与刷新状态可见。Codex 原生电脑工具初始化超时，因此未声称完成外部桌面交互验证；截图单独运行，不进入正式性能数据。

### 中断与处置

2026-10-28，短检查的两种面板各 2 次重复开关及缺失资源失败路径已完成。随后启动默认可进入任务栏的窗口反复创建/关闭；用户报告任务栏卡死，立即停止测试并清理本轮 4 个进程，确认无残留。用户随后确认任务栏恢复。

纯 WPF 的 100 次技术循环已完成；混合模式中断，未形成完整 100 次结果。整个正式对照因干扰日常桌面而不被接受，不使用其数据宣称架构达标或没有泄漏。短检查的经过筛选的汇总见 [证据记录](evidence/p0-ui-20261028-smoke.json)，只证明当次有限路径可运行。

收尾修订：两个原型窗口设置 ShowInTaskbar=false；重复开关默认次数改为 0。此次修订只重新构建，不再启动窗口，故“不会再干扰桌面”尚未经过运行验证。后续压力实验必须在独立测试会话或虚拟机完成，并先验证桌面交互不受影响。

主方案仍为 .NET + WPF / 按需 WebView2；本实验不足以最终决定混合或纯 WPF。24 小时稳定性、完整资源预算及其余 P0 检查继续保留为未完成。
