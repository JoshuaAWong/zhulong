## 1. 文档职责与依据

本文件是新版功能范围、用户决策和待决问题的统一属主；设计文件解释如何实现，实施文件安排任务与验收。后续更新先改对应属主，再同步引用，不在三份文件重复维护同一份决策表。

用户本轮确认：“先确定方向，开始完善文档框架，有疑问的向我提问”；关于迁移补充：“设计方案完全迁移到新版，旧的记录可保留”。据此，现有功能要求与产品设计完整承接，历史文档及数据保留；这不等同于授权自动导入、覆盖或删除历史数据库。

现状核对基线为 main 的 `cc6eef1`：仍是 Python 托盘应用。另有本地 `feat/pool-drain` 的 `e38badd` 及其前置提交，含进程池功能；本次文档不合并这些提交，也不把它们当作已发布 main 能力。迁移前必须单列核对，避免遗漏。

## 3. 总体目标与边界

- 持续观察系统资源、识别异常、解释波动，并在既有白名单和安全链约束内处置。
- 整合 AI 工具的用量、费用、额度与桌面交互，形成统一产品，保留烛龙品牌。
- 保留 CLI 诊断入口，让用户与 AI 能读出同一套指标、事件和原因。
- 不做磁盘垃圾/注册表清理，不自动扩大 kill 或服务重启白名单，不把普通异常升级为任意进程处置。
- 重构授权不包含改变操作系统设置、卸载旧版、删除历史数据或跳过已有动作确认。
- 多设备 AI 数据同步属于后续可选能力；不因此扩展为企业级远程系统管理平台。

## 5. 产品设计完整承接

- 烛龙是一套完整品牌：龙元素、手绘框架、卷首 Logo、favicon、朱砂印章等协调使用，候选视觉需可筛选。
- 保留昼夜双态：宣纸/漆器、墨色/暗金；两套主题分别验收可读性、对比度与状态色。
- 主布局保留左侧排行、中央监控分区、右侧朱批记事；随分辨率调整，左右区域适当加宽以减少无意义换行。
- 保留三栏界格、数据条、安/慎/危判词、焦点待办和二次确认；分区框架柔和，龙鳞底纹/水印/角花克制使用。
- 图表高度统一；有物理上限的指标使用绝对量程，不随近期峰值自动缩放；无固定上限的指标需明确单位和量程策略。
- 数字字体、字号和字距统一；所有指标、图例与事件有中文解释，技术标识按需附注。
- 干支与四季题跋随时间变化，不能把某个季节文案写死。
- AI 用量、宠物、挂件等延续同一设计语言，不能拼接成两套互不一致的产品。

## 6. 资源与可靠性验收框架

以下是待测协议与硬性行为约束，不是已达到的性能结果。数值预算在 P0 同负载测量后确认，不将旧版“80MB”直接套到含全部 WebView 子进程的新版。

| 编号 | 验收项 | 测量或判据 |
|---|---|---|
| N-01 | 后台基线 | 仅系统监控、监控+AI、完整桌面能力分别测；记录主进程及自有辅助进程 CPU、private commit、working set、句柄和读写字节 |
| N-02 | 界面生命周期 | 仅在隔离测试会话或虚拟机进行连续开关面板 100 次；先完成单次无干扰检查，每次释放控制器/事件/计时器；关闭所有 WebView 界面后自有 WebView 进程在约定期限退出，资源回落；期限由 P0 定标 |
| N-03 | 长时稳定 | 至少 24 小时，记录预热后内存/句柄趋势、失败次数与采样延迟；增长容忍值和观察窗口须在正式验收前定标 |
| N-04 | 工作量与交互 | 同一日志集测首次扫描/无变化/追加/重写；记录读取字节、耗时及界面 P95 响应；扫描不阻塞系统关键采样 |
| N-05 | 正确性 | Windows 指标独立对账；AI token/缓存/费用用人工核定样例；不能用被测逻辑生成预期结果 |
| N-06 | 失败与恢复 | 采集异常、文件占用/截断、数据库写失败、服务重启失败、休眠恢复和退出竞态都要真实触发测试 |
| N-07 | 动作与隐私 | 未授权对象、路径不可读、PID 复用和重复触发均不得绕过安全链；默认关闭可选云端功能，外联可枚举、可关闭 |

## 8. 历史规则如何适用新版

继承动作白名单、保护对象、时间语义、隐私、最小依赖、中文文档与验证纪律。旧版“4 个 pip 包”“源码即部署、不打包”“添加 Python 文件自动发现”等是旧实现约束，不机械搬到 C#；新依赖逐项论证，新发布方式以 DEC-08 为准；Q-02 保留决策记录。

现有程序与安装方式在重构验收通过前继续有效。新文档的框架状态不得改变 README 对当前可用版本的描述，也不代表重构已上线。
